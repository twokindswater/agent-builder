# Service & Directory Structure (Microservice-oriented)
[This section outlines the project's structure from a microservice perspective, defining the components and their corresponding directory layout to guide development.]

- **Backend (e.g., FastAPI)**: Organized by service domains.
  - `app/services/`: Each subdirectory represents a microservice component.
    - `auth/`: Handles user authentication and authorization.
      - `router.py`: API routes for `/auth/...`
      - `service.py`: Core business logic for authentication.
      - `schemas.py`: Pydantic schemas for request/response validation.
    - `agent/`: Manages the lifecycle of AI Agents.
      - `router.py`: API routes for `/agents/...`
      - `service.py`: CRUD logic for agents.
      - `models.py`: Database models (e.g., SQLAlchemy).
    - `workflow/`: Manages workflow creation, execution, and monitoring.
      - `router.py`: API routes for `/workflows/...`
      - `service.py`: Business logic for workflow management.
      - `executor.py`: The engine responsible for running workflows.
  - `app/core/`: Shared components and utilities used across services.
    - `database.py`: Database connection and session management.
    - `config.py`: Centralized configuration settings.

- **Frontend (e.g., React)**: Organized by features and component types.
  - `src/pages/`: Top-level components representing a full page view (e.g., `DashboardPage.tsx`, `LoginPage.tsx`).
  - `src/components/`: Reusable UI components.
    - `common/`: General-purpose components like `Button.tsx`, `Modal.tsx`.
    - `features/`: Components specific to a feature domain.
      - `agent/`: Components for agent creation, listing, etc.
      - `workflow/`: Components for the workflow builder, node editor, etc.
  - `src/services/` or `src/api/`: Functions for making API calls to the backend services.
    - `authApi.ts`, `agentApi.ts`, `workflowApi.ts`.
  - `src/store/`: Global state management setup (e.g., Redux, Zustand).
